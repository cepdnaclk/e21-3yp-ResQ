# Phase 2 MQTT Contract Matrix

## Namespace and identity decisions

- Canonical namespace: `resq/{deviceId}/...`
- Inbound LocalHub compatibility namespace: `resq/manikins/{deviceId}/...`
- Firmware publishes and subscribes only in the canonical namespace.
- The device ID in the topic is authoritative. `device_id` or `deviceId` in a payload is compatibility data and may be omitted.
- A payload device-ID mismatch must ultimately be logged and rejected or quarantined. Current code enforces this for normalized session telemetry, but not uniformly for status, heartbeat, debug, sensor-stream telemetry, or events.
- Firmware `ts_ms` is monotonic uptime in milliseconds, not Unix time. LocalHub liveness and persistence timestamps use backend receive time.
- `boot_id` and `state_seq` order state-bearing messages within and across firmware boots. They are currently added to status, heartbeat, and event/reply payloads, but not telemetry or debug snapshots.

QoS values in this table are the effective defaults in firmware and LocalHub. Only `status` is retained.

## Command contract

All commands are published by LocalHub with QoS 1 and `retained=false`. LocalHub persists a `PENDING` request before publish, then records `PUBLISHED`, `FAILED`, timeout, or a correlated reply. Firmware subscribes to `resq/{deviceId}/cmd/#` at QoS 1 and caches correlated responses for idempotent redelivery.

| Topic | Publisher | Consumer | QoS | Retained | Allowed context | Current fields | Required fields | Suspected unnecessary fields |
| ----- | --------- | -------- | --: | -------- | --------------- | -------------- | --------------- | ---------------------------- |
| `resq/{deviceId}/cmd/debug` | LocalHub | Firmware state handlers | 1 | No | State-dependent; direct sensor must be idle | `request_id`, `issued_at_ms` | `request_id` | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/telemetry` | LocalHub | Firmware telemetry publisher | 1 | No | Sensor stream outside active calibration/session ownership | `request_id`, `issued_at_ms`, `action`, optional `interval_ms` | `request_id`, `action=START|STOP`; valid `interval_ms` for START | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/calibration/start` | LocalHub | Firmware calibration state manager | 1 | No | Ready calibration-capable state, no conflicting sensor owner | `request_id`, `issued_at_ms`, hall/pressure reference inputs, optional profile identity/version/hash, interval/window, depth and kPa scaling | `request_id` and firmware-required calibration inputs | `issued_at_ms` is not used by firmware; profile metadata is repeated in result evidence |
| `resq/{deviceId}/cmd/calibration/cancel` | LocalHub | Firmware calibration state manager | 1 | No | Calibration running | `request_id`, `issued_at_ms` | `request_id` | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/session/start` | LocalHub active-session service | Firmware session manager | 1 | No | Calibrated and ready; no active session | `request_id`, `issued_at_ms`, `session_id`, `profile_id`, optional profile version/hash | `request_id`, `session_id`, accepted profile identity | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/session/stop` | LocalHub active-session service | Firmware session manager | 1 | No | Matching session active | `request_id`, `issued_at_ms`, `session_id` | `request_id`, matching `session_id` | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/system/retry` | LocalHub | Firmware recovery handlers | 1 | No | Recoverable error/calibration-fail context | `request_id`, `issued_at_ms` | `request_id` | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/system/reset` | LocalHub | Firmware recovery handlers | 1 | No | State-dependent | `request_id`, `issued_at_ms` | `request_id` | `issued_at_ms` is not used by firmware |
| `resq/{deviceId}/cmd/system/flush-config` | LocalHub | Firmware recovery handlers | 1 | No | State-dependent, destructive to stored configuration | `request_id`, `issued_at_ms` | `request_id` | `issued_at_ms` is not used by firmware |

## Compatibility behavior

LocalHub subscribes to `resq/manikins/+/{status,heartbeat,telemetry,debug,events,events/calibration,events/error}` and `resq/manikins/+/live`. The legacy `live` suffix is normalized to telemetry. Compatibility messages update runtime views but are not inserted by `persistCanonicalMessage`; canonical messages are persisted before message-specific validation and dispatch.

The shared TypeScript `firmwareTopics` parser recognizes only the canonical namespace. Browser clients consume REST/SSE and do not subscribe to MQTT directly.
